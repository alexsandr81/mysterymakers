# MysteryMakers — интернет-магазин на Laravel

**MysteryMakers — майстерня виробів з фанери.** Фанера и МДФ (коробки, брелки, чайные домики, детская посуда и др.),
а также модели и изделия из 3D-печати; в будущем — товары, связанные с электроникой.

Магазин на Laravel: светлая тема с тёплой древесной палитрой, два языка (украинский / русский), цены в гривнах.
Репозиторий: https://github.com/alexsandr81/mysterymakers

## 1. Что есть в магазине

### Витрина (для покупателей)
- Главная со слайдером баннеров (автопрокрутка), название, подпись и описание магазина.
- Каталог: категории с выпадающими подкатегориями, фильтр по цене, наличию и характеристикам, сортировка, пагинация, поиск (название на обоих языках + артикул).
- Карточка товара: галерея до 5 фото, увеличение фото под курсором, цена и скидка («старая цена»), артикул, **размер изделия в мм**, характеристики, отзывы (после модерации), кнопка ♡ «в избранное».
- Корзина и оформление заказа (гость или пользователь): имя и фамилия, телефон, доставка **Новой Почтой** (город и отделение/почтомат выбираются из списка Новой Почты) или **Укрпоштой** (город и индекс), оплата: **наложенный платёж** или **оплата на карту** (предоплата переводом; реквизиты владелец отправляет клиенту сам сообщением, затем отмечает заказ оплаченным в админке).
- Регистрация и вход, **вход через Google**, восстановление и смена пароля.
- Личный кабинет: данные, смена пароля (ссылка «Сменить пароль»), история заказов с фото, артикулом и названием товара (кликабельно), избранное.
- **Тёмная тема:** кнопка 🌙 / ☀️ в шапке сайта и в меню админки; по умолчанию берётся настройка устройства, выбор запоминается в браузере. Цвета темы — переменные в конце `public/css/app.css`.
- Переключатель языка UK / RU; страницы: «Про нас», «Доставка и оплата», «Контакты» и любые свои.
- Подвал: несколько телефонов (с кнопками Viber / WhatsApp / Telegram), email, адрес, ссылки на страницы.

### Письма
- Клиенту: подтверждение заказа и смена статуса — оформлены в стиле магазина, с фото товаров, на языке, который клиент выбрал при заказе. Ссылка для сброса пароля.
- **Владельцу: письмо о каждом новом заказе** (на русском, со ссылкой на заказ в админке).
- В письмах стоит Reply-To на email магазина, подвал берётся из настроек.

### Админка (`/admin`, только для администраторов)
| Раздел | Что делает |
|---|---|
| 📊 Дашборд | Период 7/30/90 дней; выручка, число заказов, средний чек; график продаж по дням; топ товаров; статусы заказов; товары на исходе; последние заказы |
| 🛒 Заказы | Список, смена статуса (письмо клиенту), удаление, **счётчик новых заказов в меню (обновляется сам раз в 20 секунд, при новом заказе — всплывающее уведомление и звук; включается кнопкой «🔔 Звук» в меню, после перезагрузки страницы нужен один клик на ней)**, ссылки на товары и на клиента, накладная Новой Почты |
| 📦 Товары | Сортировка по клику на заголовок колонки (название, артикул, категория, цена, остаток, активен, дата), поиск, создание/правка/удаление, до 5 фото (автосжатие), выбор главного фото (обложки), скидка, характеристики, **автоартикул по категории**, **размер в мм** |
| 💬 Отзывы | Модерация (одобрить / скрыть / удалить), счётчик ожидающих в меню |
| 👥 Пользователи | Поиск, правка данных, смена пароля, права администратора, удаление (заказы сохраняются) |
| 📦 Товары: массовая цена | В списке товаров отметьте товары галочками (или «Отметить с ценой …», или «Ко всем из поиска») и измените цену: +/− %, +/− грн или установить; с округлением до 1/5/10 грн. Старая цена (скидка) снимается, если новая цена её достигла |
| 📦 Товар: категория на лету | В форме товара категория и подкатегория выбираются отдельно; пункты «＋ Новая категория…» и «＋ Новая подкатегория…» создают их прямо при сохранении товара (блок артикулов и папка на Google Диске назначаются автоматически) |
| 🎉 Праздники | Тематические метки товаров (Новый год, 8 Марта…): раздел «Праздники», выбор в карточке товара (несколько), новый праздник можно создать прямо в форме товара; в каталоге — фильтр «Праздник / повод» |
| 📁 Категории | Категории и подкатегории визуально разделены (бейджи, отступ), у категории кнопка «＋ Подкатегория» |
| 🧮 Калькулятор | Расчёт цены изделия: фанера/МДФ (материал с учётом обрезков + резка + гравировка) и/или 3D-печать (граммы филамента × цена за грамм из таблицы «Филамент») + прочее → накладные → наценка → цена. Материалы, цены листов, тарифы резки, наценка и округление редактируются на странице, показывается, когда цена листа проверялась последний раз |
| 📂 Категории | Дерево категорий, диапазон артикулов (блок 10000 на категорию, подблоки по 1000 на подкатегории), порядок на сайте кнопками ▲▼ (среди категорий одного уровня), сортировка по клику на заголовок колонки |
| 🏷 Характеристики | «Материал», «Цвет» и т. п. и их значения; участвуют в фильтрах каталога |
| 🖼 Баннеры | Слайдер на главной |
| 📄 Страницы | Любые текстовые страницы + дополнительные разделы с жирным заголовком (график работы, email и т. п.) |
| ⚙ Настройки | Название, подпись и описание магазина (uk/ru), телефоны, email, email для уведомлений о заказах, адрес |
| 📦 Новая Почта | Данные отправителя для накладных, вес и габариты коробки по умолчанию |
| 💾 Копии | Резервные копии: создать, скачать, удалить |

### Технически
- Остатки списываются при заказе (транзакция, блокировка строк), при отмене/удалении возвращаются.
- Фото автоматически уменьшаются (до 1600 px; баннеры до 1920 px) и сохраняются в WebP/JPEG (нужен PHP GD — в Laragon включён).
- SEO: `/sitemap.xml`, `robots.txt`, canonical, Open Graph, микроразметка товара (цена, наличие, рейтинг).
- Защита: CSRF, права администратора (403 для остальных), валидация, ограничение частоты запросов, пароли и ключи только в `.env`.
- Номера заказов — только цифры (1001, 1002…).
- Автотесты (`php artisan test`).

## 2. Установка и запуск

### Один раз поставить инструменты (Windows)
Проще всего **[Laragon (Full)](https://laragon.org/download/)** — в нём PHP, Composer и MySQL. Нужны PHP 8.2+ и Composer.
Локально используется SQLite, отдельный MySQL не нужен.

### Развернуть проект
В терминале Laragon, в папке с репозиторием (у нас `C:\laragon\www\mysterymakers`):
```
setup.bat          (Windows)
./setup.sh         (Linux / macOS)
```
Скрипт скачает чистый Laravel в папку `shop`, положит туда файлы магазина, создаст базу и демо-товары.

### Запустить
```
cd C:\laragon\www\shop
php artisan serve
```
Сайт: http://127.0.0.1:8000 · Админка: http://127.0.0.1:8000/admin

Первый вход: `admin@mysterymakers.local` / `admin12345` — **сразу смените пароль**
(админка → Пользователи → ваш аккаунт, либо в личном кабинете «Сменить пароль»).

> Важно: команды `php artisan ...` выполняются **в папке `shop`** (`cd C:\laragon\www\shop`), а не в `www` и не в папке репозитория.

## 3. Обновление сайта (рабочий процесс)

Репозиторий — это «наложение» (overlay): папки `app, config, database, lang, public, resources, routes, tests`
копируются поверх чистого Laravel в `shop`. Всё, что вы видите на сайте, живёт в `shop`; репозиторий — источник файлов.

Когда в репозитории появились новые функции:
```
cd C:\laragon\www\mysterymakers
git pull
update.bat "C:\laragon\www\shop"
```
`update.bat` копирует новые файлы, применяет миграции, добавляет демо-страницы/характеристики (существующее не перезаписывает)
и чистит кэши. **Данные (товары, заказы, пользователи, ваши пароли) не затрагиваются.**

После изменения `.env` выполните в `shop`:
```
php artisan config:clear
```
и перезапустите `php artisan serve`.

### 4.1. Роли: администратор и модератор

Роль задаётся в «Пользователи» → «Изменить» → «Роль». Человек сначала регистрируется на сайте как обычный покупатель, потом администратор меняет ему роль.

У модератора **те же права, что у администратора**, кроме трёх: он не видит раздел «Пользователи» (смена ролей и удаление пользователей), не видит «Действия модератора» и не может снимать метку «проверено».

Что видит администратор:
- Журнал «🔔 Действия модератора»: кто, когда и что добавил, изменил или удалил, со ссылкой на товар. Новые записи подсвечены, в меню стоит счётчик.
- Всплывающее уведомление (раз в 20 секунд сайт проверяет новые действия, как и новые заказы), со звуком, если он включён.
- Метку «⏳ проверить» у товаров, которые добавил или изменил модератор, счётчик у «Товары» и фильтр «Ждут проверки» в списке товаров.

Как снять метку: открыть товар и сохранить с галочкой «Проверено» (она стоит по умолчанию), либо нажать ✔ в списке, либо отметить несколько товаров и нажать «Отметить выбранные проверенными». Если модератор потом правит проверенный товар, метка возвращается, а на сайте товар остаётся как был.

Цену модератор может не указывать: на сайте у такого товара написано «Цена уточняется», и купить его нельзя, пока цена не задана.

## 5. Пошаговая настройка внешних сервисов

### 5.1. Отправка писем (Gmail)
Без настройки письма не отправляются, а пишутся в `storage/logs/laravel.log` (`MAIL_MAILER=log`).

1. Включите двухэтапную аутентификацию в аккаунте Google: https://myaccount.google.com/security
2. Создайте «пароль приложения»: https://myaccount.google.com/apppasswords — назовите, например, «Магазин», Google покажет 16-значный пароль (показывается один раз).
3. Впишите в `shop\.env` строки из блока «Почта» выше. **Пароль — без пробелов**, и строка `MAIL_PASSWORD=` должна присутствовать.
4. `php artisan config:clear`, перезапустите `php artisan serve`.
5. Проверьте: оформите тестовый заказ — клиенту и владельцу придут письма.

Если письмо не уходит, заказ всё равно оформляется, а причина записывается в `storage/logs/laravel.log`.
На хостинге используйте SMTP хостинга или сервис рассылок (Brevo, Mailgun, Resend и т. п.). Свой адрес вида `info@домен` — после покупки домена
(бесплатный Zoho Mail требует собственного домена и не подходит для SMTP на бесплатном тарифе).

Куда приходят уведомления о заказах: «⚙ Настройки» → «Email для уведомлений» (если пусто — на Email магазина).

### 5.2. Вход через Google
Кнопка «Войти через Google» появляется на страницах входа и регистрации, только когда в `.env` заданы ключи.

1. Откройте https://console.cloud.google.com/ → создайте проект.
2. **APIs & Services → OAuth consent screen** (тип External; название и ваш email; пока приложение в режиме Testing, добавьте свой Gmail в «Test users»).
3. **Credentials → Create credentials → OAuth client ID → Web application**.
4. В **Authorized redirect URIs** добавьте (для локальной работы оба):
   - `http://127.0.0.1:8000/auth/google/callback`
   - `http://localhost:8000/auth/google/callback`

   На хостинге добавьте `https://ваш-домен/auth/google/callback`.
5. Скопируйте Client ID и Client secret в `shop\.env` (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`).
6. `php artisan config:clear`, перезапустите `php artisan serve`.

Если у человека уже есть аккаунт с тем же email, Google-вход привяжется к нему.
Для публичного запуска переведите приложение из режима Testing в Production (в OAuth consent screen).

### 5.3. Новая Почта: API-ключ
Нужен для: выбора города и отделения из списка при оформлении и для создания накладных.

1. Войдите в бизнес-кабинет: https://business.novaposhta.ua/ (нужна регистрация как отправитель/контрагент).
2. **Налаштування → Безпека → Ключі API → Створити**.
3. Впишите в `shop\.env`: `NOVAPOSHTA_API_KEY=ваш_ключ`, затем `php artisan config:clear`.

Без ключа на форме заказа показываются обычные текстовые поля «Город» и «Отделение», накладные недоступны.

Полезные ссылки: личный кабинет отправлений — https://my.novaposhta.ua/ · отслеживание посылки — https://novaposhta.ua/tracking/ · поиск отделений Укрпошты — https://index.ukrposhta.ua/

### 5.4. Google Диск: папки категорий и товаров
Сайт сам создаёт на вашем Google Диске папки по структуре каталога:
`MysteryMakers / Категория / Подкатегория / 11000 Название товара`. Папка товара создаётся пустой — файлы вы кладёте в неё сами.
Переименовали категорию или товар на сайте — папка переименуется; сменили категорию — папка переедет. Удаление на сайте папки на Диске **не удаляет**.

1. Откройте https://console.cloud.google.com/ → создайте проект (или возьмите тот же, что для входа через Google).
2. **APIs & Services → Library** → найдите **Google Drive API** → **Enable**.
3. **APIs & Services → Credentials → Create credentials → Service account**. Имя любое (например `mysterymakers-drive`), роли не нужны → **Done**.
4. Откройте созданный сервисный аккаунт → вкладка **Keys → Add key → Create new key → JSON**. Скачается файл. Положите его в `C:\laragon\www\shop\storage\app\google-drive.json`. **Никому не показывайте и не отправляйте этот файл.**
5. Скопируйте email сервисного аккаунта (вида `...@...iam.gserviceaccount.com`).
6. На Google Диске создайте папку **MysteryMakers** → «Поделиться» → вставьте этот email → права **Редактор**.
7. Откройте папку: в адресе будет `.../folders/ВОТ_ЭТО_ID` — скопируйте этот id.
8. В `shop\.env` допишите: `GOOGLE_DRIVE_ROOT_ID=ВОТ_ЭТО_ID`, затем `php artisan config:clear`.
9. Если в папках товаров остались старые подпапки «Фото» и «Чертежи», `php artisan shop:drive-flatten` перенесёт их файлы в папку товара и уберёт пустые подпапки в корзину Диска.
10. Для уже существующих категорий и товаров выполните `php artisan shop:drive-sync` — создаст недостающие папки. В списках админки у каждой строки появится 📁 (ссылка на папку) или 📁+ (создать папку).

Если Диск недоступен, категория или товар всё равно сохранятся, а в сообщении будет пометка; подробности — в `storage/logs/laravel.log`. Без настройки ничего не происходит.

## 6. Накладные Новой Почты

Один раз:
1. Убедитесь, что `NOVAPOSHTA_API_KEY` задан ([5.3](#53-новая-почта-api-ключ)), а в кабинете есть контрагент-отправитель.
2. Админка → **📦 Новая Почта**: контрагент и контактное лицо (подгружаются из аккаунта), телефон, **город и отделение отправки** (выбираются из списка), вес и габариты коробки по умолчанию (мм/см), описание груза. Сохраните.

Для каждого заказа:
1. Откройте заказ (должна быть доставка Новой Почтой с городом и отделением, выбранными из списка).
2. В блоке «Накладная Новой Почты»: проверьте **имя и фамилию получателя — только кириллицей** (Новая Почта не принимает латиницу), при необходимости раскройте «Вес и габариты», выберите, кто платит за доставку, нажмите **«Создать накладную»**.
3. Наложенный платёж: сумма заказа ставится как обратная доставка. Если заказ оплачен заранее — обратная доставка не добавляется.
4. **Почтомат:** если клиент выбрал почтомат, в заказе это помечено (лимит — до 20 кг; накладная с большим весом не создаётся).
5. **Адресная доставка (курьер Новой Почты):** клиент выбирает в форме оформления «Новая Почта — адресная доставка» и вводит город и улицу (из списка), дом и квартиру. Накладная создаётся с услугой «склад → двери», адрес получателя регистрируется автоматически.
6. После создания доступны: 🖨 печать PDF, ↻ обновление статуса посылки, удаление накладной.

Габариты нужны Новой Почте, так как плата берётся по большему из реального и объёмного веса; указанные «по умолчанию» подставляются автоматически — менять их нужно только для нестандартной коробки.

## 7. Резервные копии, тесты, SEO

### Резервные копии
- Админка → **💾 Копии** → «Создать резервную копию» (скачать/удалить копии там же) или команда `php artisan shop:backup` (`--keep=N` — сколько хранить, по умолчанию 10).
- В архив входят база (SQLite) и все загруженные фото, лежит в `shop\storage\backups`.
- **Нужно расширение PHP `zip`:** Laragon → правый клик по значку → PHP → Extensions → zip, перезапустить сервер.
- Файл `.env` в архив не входит — храните его отдельно. Скачанную копию лучше хранить на другом диске или в облаке.
- На MySQL (хостинг): базу выгружайте средствами хостинга (`mysqldump` / phpMyAdmin).

### Тесты
```
cd C:\laragon\www\shop
php artisan test
```
Проверяют: открытие страниц, права администратора, оформление заказа с письмами и списанием остатка, модерацию отзывов, избранное.

### SEO
- `/sitemap.xml` — карта сайта; `public/robots.txt` — закрывает админку, корзину, кабинет.
- После переноса на домен добавьте в `public/robots.txt` строку `Sitemap: https://ваш-домен/sitemap.xml` и подайте карту в [Google Search Console](https://search.google.com/search-console).
- Описание магазина (⚙ Настройки) используется как meta description по умолчанию; у товаров — микроразметка Product.

## 8. Безопасность

- **Никогда не публикуйте и не пересылайте** содержимое `.env`: пароль приложения Gmail, Google Client secret, ключ Новой Почты, пароли БД. Если секрет случайно попал в чат/репозиторий — немедленно удалите его и создайте новый.
- `.env` не должен попадать в git. В репозитории секретов нет.
- Смените пароль по умолчанию `admin12345` и email администратора.
- На хостинге: `APP_ENV=production`, `APP_DEBUG=false`, HTTPS, документ-рут — папка `public`.
- Файлы резервных копий содержат данные клиентов — не оставляйте их в открытом доступе.

## 9. Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `Could not open input file: artisan` | Команда запущена не в папке `shop`. `cd C:\laragon\www\shop` |
| Письмо «отправилось», но не пришло | В `.env` нет строки `MAIL_PASSWORD` или пароль с пробелами; после правки `.env` — `php artisan config:clear` и перезапуск; смотрите `storage/logs/laravel.log` |
| «В PHP не включено расширение zip» | Laragon → PHP → Extensions → zip, перезапуск |
| `update.bat`: «no such column…» / ошибка миграции | Пришлите текст ошибки; миграции написаны так, чтобы повторный запуск был безопасен |
| Накладная: «FirstName has invalid characters» | Имя/фамилия получателя не кириллицей — исправьте в форме накладной |
| Накладная: «DateTime cannot be less then now» | Часовой пояс сервера; в `.env` задайте `APP_TIMEZONE=Europe/Kyiv` (в коде дата уже берётся по Киеву) |
| Накладная: ошибки отправителя | Заполните «📦 Новая Почта» и выберите город/отделение из списка |
| Нет списка городов/отделений НП на оформлении | Не задан `NOVAPOSHTA_API_KEY` или не выполнен `config:clear` |
| Нет кнопки «Войти через Google» | Не заданы `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` или не выполнен `config:clear` |
| Ошибка Google redirect_uri_mismatch | Адрес обратного вызова в консоли Google не совпадает: добавьте оба адреса из [5.2](#52-вход-через-google) |
| Логи | `shop\storage\logs\laravel.log` |

## 10. Как расширять проект

| Что нужно | Куда смотреть |
|---|---|
| Добавить товар / категорию | Админка → Товары / Категории |
| Текстовая страница | Админка → Страницы (адрес `/page/<адрес>`, ссылка попадает в подвал) |
| Баннер | Админка → Баннеры |
| Материал, цвет и т. п. | Админка → Характеристики, затем выбрать в карточке товара |
| Страница со своей логикой | маршрут в `routes/web.php` + контроллер + шаблон с `@extends('layouts.app')` |
| Цвета | переменные в начале `public/css/app.css` |
| Тексты интерфейса | `lang/uk/shop.php`, `lang/ru/shop.php` (письма — `mail.php`) |
| Новое поле у товара | миграция (`php artisan make:migration`) + `app/Models/Product.php` + форма в админке. Не правьте уже применённые миграции — создавайте новые |
| Новый способ доставки/оплаты | `Order::DELIVERY` / `Order::PAYMENT` и тексты в `lang/*/shop.php` |

Структура: `app/Models` — данные, `app/Http/Controllers` — логика, `app/Services` (корзина, Новая Почта, письма),
`app/Console/Commands` — команды (`shop:backup`), `resources/views` — шаблоны, `database/migrations` — структура базы, `tests` — тесты.

## 11. Перенос на хостинг и домен

Сейчас магазин работает только локально. Когда всё будет готово:
1. Купить домен и хостинг с **PHP 8.2+** и MySQL (проще всего — с SSH).
2. Загрузить проект (папку `shop`), выполнить `composer install --no-dev --optimize-autoloader`.
3. Создать базу MySQL; в `.env`: `DB_CONNECTION=mysql`, `DB_HOST`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL=https://ваш-домен`, `APP_TIMEZONE=Europe/Kyiv`.
4. `php artisan key:generate` (если ключа нет), `php artisan migrate --seed --force`, `php artisan storage:link`.
5. Document root — папка `public`.
6. Сменить пароль администратора, удалить демо-товары.
7. Обновить внешние сервисы: добавить `https://ваш-домен/auth/google/callback` в Google Cloud, настроить SMTP хостинга/почту на домене, добавить `Sitemap:` в `robots.txt`, подать сайт в Search Console.
8. Настроить регулярные резервные копии (`php artisan shop:backup` по расписанию cron + выгрузка MySQL).

## 12. Чего пока нет

**Запланировано:**
- Автоматический приём оплаты картой через платёжный сервис (LiqPay, Monobank, WayForPay — нужен ФОП/юрлицо). Сейчас работает ручная «Оплата на карту».
- Промокоды и бесплатная доставка от определённой суммы.
- Персонализация изделий (поле для текста гравировки/имени в заказе).
- Продажа цифровых 3D-моделей (файлы после оплаты) — если понадобится.
- PWA (установка сайта как приложения на телефон).
- Размер изделия как фильтр каталога и автоподстановка габаритов в накладную.
- Сжатие уже загруженных старых фото (сжимаются только новые).
- Домен, хостинг и почта на домене.
- **Автоматическое отслеживание посылок Новой Почты** (когда заказов станет много, лучше делать уже на хостинге): задача по расписанию раз в час опрашивает Новую Почту по всем активным накладным, обновляет статус в заказе, переводит заказ в «Выполнен» после получения, отправляет клиенту письмо «посылка прибыла в отделение» и подсвечивает посылки, которые долго лежат или возвращаются. Для работы нужен планировщик Laravel (на ноутбуке — запуск `php artisan schedule:run` каждую минуту, на хостинге — cron).
- Роль «Менеджер» (доступ к заказам и товарам без доступа к настройкам, пользователям и копиям).
- Необязательное поле «реквизиты для оплаты на карту» в настройках, показываемое клиенту после заказа.

**Известные ограничения:**
- Автотесты написаны, но запускаются на вашей стороне (`php artisan test`).
- Статус посылки обновляется кнопкой «↻ Статус» в заказе; автоматического отслеживания пока нет (см. «Запланировано»).

## 13. Доступ с другого компьютера (ngrok)

Пока сайт работает локально, к нему можно дать доступ через бесплатный туннель [ngrok](https://ngrok.com).
На втором компьютере ничего ставить не нужно — только браузер.

**Один раз (на ноутбуке с сайтом):**
1. Зарегистрируйтесь на https://ngrok.com, скачайте программу для Windows и распакуйте в `C:\ngrok`.
2. В кабинете ngrok → **Your Authtoken** скопируйте токен (никому не показывайте; если он попал в чат или репозиторий — сбросьте кнопкой Reset).
3. В PowerShell: `cd C:\ngrok`, затем `.\ngrok config add-authtoken ВАШ_ТОКЕН`.
4. В кабинете ngrok → **Domains** уже есть бесплатный «dev domain» вида `что-то-что-то.ngrok-free.dev` — это ваш постоянный адрес (платить и создавать ничего не нужно).
5. В `C:\laragon\www\shop\.env` задайте `APP_URL=https://ВАШ-ДОМЕН.ngrok-free.dev`, затем `php artisan config:clear`.

**Каждый раз при работе (два окна):**
```
cd C:\laragon\www\shop
php artisan serve
```
```
cd C:\ngrok
.\ngrok http --url=ВАШ-ДОМЕН.ngrok-free.dev 8000
```
Ссылка для другого человека: `https://ВАШ-ДОМЕН.ngrok-free.dev/admin`. При первом заходе ngrok показывает страницу-предупреждение — нужно нажать «Visit Site».

**Важно:** сайт доступен, пока включены ноутбук, `php artisan serve` и ngrok. Для помощника создайте отдельный аккаунт администратора
(Админка → Пользователи) с надёжным паролем. Вход через Google в таком режиме не заработает, пока адрес туннеля не добавлен в
«Authorized redirect URIs» в Google Cloud. Перед тем как вернуться к `APP_URL=http://127.0.0.1:8000` (если нужно), не забудьте `config:clear`.
